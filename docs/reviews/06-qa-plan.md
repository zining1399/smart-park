## 0. 现状与总体判断

- 后端无 `src/test`、pom 无 test 依赖；前端零测试。**从零建立，与生产化改造（Security+JWT、MySQL 迁移、Docker、CI）同步落地**。
- 本系统是企业内部管理系统，并发量低，但**业务正确性（状态机、审批、逾期判定、脱敏）与数据安全（鉴权、身份证明文）风险高**。测试投入向"接口/集成层 + 鉴权矩阵 + 状态机"倾斜，而非追求覆盖率数字。
- 已发现的实现级风险（用例须针对性验证，而非假设其正确）：
  - `stockOut/approve` 先读后写无锁，**并发重复出库大概率双双成功**（TC-STK-11/22/23/24 专项验证）；
  - `ScheduledTasks` 扫描间隔 1 分钟为演示值，生产间隔【待确认】；
  - 身份证"存储全量、接口脱敏"，**列表接口是否真的脱敏须逐接口验证**；
  - 定时任务先改状态后建告警无事务，告警失败即**静默丢失**。

## 1. 测试策略

### 1.1 测试金字塔分层

| 层级 | 范围 | 自动化目标 | 工具选型（含被否决备选） |
|------|------|-----------|------------------------|
| 单元测试 | Service 层纯业务逻辑：状态机判定、逾期判定、脱敏规则、`DateTimes` 边界 | 核心业务类行覆盖 ≥70%，整体 ≥50% | **JUnit5 + Mockito**。否决 Spock（Groovy 额外语言成本）；否决 TestNG（Boot 生态默认 JUnit5，无收益） |
| 集成测试 | 9 个 Controller 全量接口 + 鉴权矩阵 + Flyway 迁移后行为，跑真实 MySQL 8 | **P0 接口 100% 覆盖（含异常分支）** | **@SpringBootTest + MockMvc + Testcontainers(MySQL 8)**。否决 H2 内存库（时间字段改型 + MySQL 特有行为会被掩盖，等于白测） |
| 数据迁移验证 | Flyway 脚本、VARCHAR→DATETIME 回填、时间范围查询 | 迁移脚本专测每次变更必跑 + 人工对账 | Testcontainers + 对账清单（自动化无法替代） |
| 前端组件 | 登录表单校验、脱敏渲染、分页表格、日期筛选 | 仅关键路径 | **Vitest + Vue Test Utils**。否决 Jest（Vitest 共享 vite.config，零额外配置） |
| E2E | 登录→各模块关键路径 | 冒烟集 ~15 条，CI 夜间 | **Playwright**。否决 Cypress（多浏览器原生支持、并行免费、Node 库易进 CI 容器） |
| 非功能 | 性能、安全、兼容、备份恢复 | 见 §3 | JMeter / OWASP ZAP / mysqldump 演练 |

目标配比（用例数量）：单测 45% : 接口集成 40% : E2E 10% : 前端组件 5%。

### 1.2 零测试基础上的补测优先级（投入产出比排序）

1. **接口集成 + 鉴权矩阵**（最高 ROI，契约即事实来源，同时兜住 Security 改造回归）；
2. **核心状态机单测**（物资/访客/权限，客户验收必测、人工回归最贵）；
3. **定时任务测试**（幂等与边界）；
4. **数据迁移专项**（失败即 No-Go）；
5. **E2E 冒烟集**（防"整系统起不来"级事故）；
6. **前端组件测试**（只测登录、脱敏、日期筛选三点）。

明确**不追求**：前端全量组件测试、80%+ 覆盖率、全模块 E2E。

### 1.3 回归策略与冒烟集

- **冒烟第一关（v1.1 新增，最高优先）**：TC-SMOKE-01 数据持久性——录入→重启→数据仍在。此关不过，其余一切测试无意义。
- **冒烟集**（<10 分钟，CI 必跑）：登录/JWT 刷新、各模块列表分页各 1 条、模拟通行 1 条、普通+贵重出库各 1 条、看板 3 接口。
- 测试数据：Testcontainers 每次起干净库，专用 test-data.sql（与生产 data.sql 分离）；E2E 独立 compose 实例。

### 2.7a 枚举校验专项（v1.3/v1.4 封版）

- **TC-ENUM-01（P0→P1 视版本）**：SQL 直插非法枚举，断言**错误号 3819 且消息含约束名**（双条件防假通过：排除 1364 缺列/1406 超长/1062 唯一冲突/1146 表不存在的"插入失败≠CHECK 拦截"误判）；17 条约束互不重复可精确定位；正向对照 4 个合法区域各插一条（生活区单独一条最易漏）；**强断言仅 `access_permission.area`**（`visitor.area` 无 CHECK 归 API 层）；结果解读表：MySQL <8.0.16 下 CHECK 静默失效 → 该用例**应判 FAIL 且 FAIL 是有效缺陷信号**，不得"改对"。
- **TC-ENUM-02（P0 硬要求）**：API 层枚举校验**无论 MySQL 版本必须拒绝**非法值（参数化：中文错字/繁体/小写/尾空格/空串 × 按表分组）。**P0 断言集 7 字段**（employee.status、vehicle.status、vehicle.owner_type、material.status、material.category、access_permission.area + visitor.area——5.7 下 API 层是唯一防线）；P1 回归集 5 字段（双层字段验证既有校验未被删）；已砍除 7 个"不接收外部输入"字段的无效参数化。PASS 基线：backend 任务 10 DTO 清单与 6 个裸奔项一一对应无遗漏（已核对），**5.7 环境下 7 个 P0 字段任何 FAIL = backend DTO 漏项，按清单直接定位**。建议该用例组进 CI merge 门禁。
- **TC-ENUM-03a（P1）**：尾空格 `'PERSON '`——8.0.16+ (NO PAD) 拒绝 / 降级 general_ci (PAD SPACE) 放行（双分支，与 collation 降级决策联动）。
- **TC-ENUM-03b（P1）**：小写 `'person'`——DB 两种 collation 均放行为**正确预期**（确认设计行为）；**API 路径必须拒绝**（@Pattern 大小写敏感，不加 (?i)——若放行说明有人误加了 i flag）。「DB 放行 + API 拒绝」组合 = 防线分层正确性交叉验证。
- **TC-ENUM-04（P2）**：3 个可空字段（vehicle.owner_type / access_record.direction / material.category）SQL 直插 NULL 成功——防 NOT NULL 误套与 DDL 变更回归。
- 配套**「枚举字段 × 防线归属」三层总表**（🔴裸奔 6 字段 / 🟡仅 API / 🟢双层 / ⚪不接收外部输入，17+2 字段）：执行人与后端一眼可见某字段缺哪层防线。

## 5. 上线验收清单（Go / No-Go）

**功能与数据**：P0 全过（0 失败）；P1 通过率 ≥95% 且定级跟踪；迁移对账（行数+每表抽 20 条）；README 9 条假设客户书面确认。
**安全**：鉴权矩阵（44 接口×3 角色）全过；身份证脱敏逐接口抓包；h2-console/actuator/Swagger 生产关闭、CORS 同源化；ZAP 无 High 以上；密码哈希方案验证。
**部署与运维**：镜像在**客户同规格环境**拉起成功；生产配置无演示值残留（扫描间隔 1 分钟、H2 URL 等）；备份恢复演练完成留记录；日志落盘轮转就绪；回滚可行（旧镜像+数据快照现场留存）。
**性能**：目标达成或客户书面降低。
**文档与培训**：部署/运维/用户手册交付；三角色现场培训签到；已知缺陷清单客户签字。
**CI**：流水线含后端单测+集成（Testcontainers）、前端 build+Vitest、E2E 夜间；主分支合并被测试失败阻断。

**硬性 No-Go（任一命中即停）**：① 未修复 Blocker；② 迁移对账不一致；③ 任何越权用例成功；④ 身份证任何响应/日志明文；⑤ 备份恢复演练未做或失败；⑥ 客户未书面确认 9 条假设；**⑦ TC-SMOKE-01 重启丢数据未修复**。

## 6. UAT 方案

三方参与（客户业务人员 2~3 名按角色分 + 我方 PM/开发 + 测试记录），2~3 个工作日；客户现场独立 UAT 环境 + **脱敏仿真数据**（按客户真实门岗/部门/物资造数 50~100 条，不得用演示种子冒充）；从清单选 ~40 条（全部 P0 业务流 + 高频操作 + 每个状态机完整生命周期），按角色分发（门岗领门禁+访客、仓管领出入库、管理员领全量）；客户业务人员按记录表逐步操作勾选，我方只引导不代操作；出《UAT 结果报告》→《遗留问题及修复计划》→ 双方签署《验收确认单》进入质保期；范围外新需求记《需求变更备忘》不阻塞验收。
