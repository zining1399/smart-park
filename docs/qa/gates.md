## 3. 缺陷分级与修复时限

| 级别 | 定义 | 修复时限 | 放行影响 |
|---|---|---|---|
| **Blocker** | 系统起不来；核心状态机错乱（双重出库、审批后物资状态错）；鉴权形同虚设；身份证明文落库或泄漏；迁移数据丢失；重启丢数据 | **24 小时内** | 存在任何未修复 → **No-Go** |
| **Critical** | 主流程不可用（check-in 失败、告警不产生）；统计数据错误；并发缺陷；时间偏移 8 小时 | **3 个工作日内 + 回归** | 未修复 ≤ 2 个且有绕行方案 + 客户书面认可 → 有条件 Go；否则 No-Go |
| **Major** | 次要功能缺陷；边界场景错误；性能未达标但有缓解措施 | 上线后 2 周内 | 允许带缺陷上线，须进已知问题清单并获客户确认 |
| **Minor** | UI 瑕疵、文案、不影响业务的校验缺失 | 上线后 backlog | 无影响 |

### 3.1 已知预判项（修复前预期必挂，用于验证修复效果）

| 预判缺陷 | 用例 | 级别 | 责任方 |
|---|---|---|---|
| 重启清库（init.mode + DROP TABLE） | TC-SMOKE-01 | Blocker | backend / devops |
| 并发重复出库 | TC-STK-11 | Blocker | backend |
| 并发重复审批 | TC-STK-22 | Blocker | backend |
| 并发重复归还 | TC-STK-23 | Blocker | backend |
| 出库/审批交叉矛盾态 | TC-STK-24 | Blocker | backend |
| UTC 环境时间偏移 8 小时 | TC-MIG-06 | Critical（客户环境为 UTC 时升 Blocker） | backend |
| API 层枚举校验缺失（6 个裸奔字段） | TC-ENUM-02 | Critical | backend |
| 前端类型筛选仍含 RETURN 选项 | TC-FE-15 | Minor（契约一致性问题） | frontend |

> 上述为**基于现状代码的预判**，用于让开发提前排期；实测后按实际结果更新。

## 4. UAT 方案（客户现场验收）

### 4.1 组织与时长
- 参与方：客户业务人员 2~3 名（按管理员/门岗/仓管分角色）、我方项目经理、开发支持、测试工程师（记录与见证）。
- 时长：**2~3 个工作日**。

### 4.2 环境与数据
- 客户现场**独立 UAT 环境**（docker-compose 或现场服务器）。
- 使用**按客户真实业务造的仿真数据**（门岗名、部门、物资类别、员工规模 50~100 条），**不使用我方演示 data.sql**。

### 4.3 用例挑选（约 40 条）
- 全部 P0 业务流；
- 客户日常高频操作：预约访客、模拟通行、普通出库归还、看板查看；
- 每个状态机各完整走一遍生命周期（物资、访客、权限时效）。

**按角色分发**：门岗领门禁 + 访客用例；仓管领出入库用例；管理员领全量 + 权限 + 看板。

### 4.4 执行与记录
- 业务人员按《UAT 执行记录表》逐步操作并勾选（用例ID / 操作人 / 时间 / 结果 / 截图）。
- **我方只引导，不代操作**（代操作的验收结果无效）。

### 4.5 签字流程
1. 每日 UAT 晨会同步缺陷；
2. 全部用例执行完 → 出《UAT 结果报告》（通过率、缺陷分级清单、遗留项承诺修复时间）；
3. Major 及以下遗留项列入附件《遗留问题及修复计划》；
4. 客户业务负责人 + 我方项目经理签署《验收确认单》（引用本文档 §2 验收标准），自签字日起进入质保期。

### 4.6 争议处理
UAT 中新提出的范围外需求**不阻塞验收**，记入《需求变更备忘》另行排期。

## 5. CI 门禁范围

| 门禁 | 内容 | 触发时机 |
|---|---|---|
| **merge 阻断** | 后端单元测试全绿 | 每次 PR |
| **merge 阻断** | 后端接口集成测试（Testcontainers/MySQL8）全绿，含鉴权矩阵冒烟子集 | 每次 PR |
| **merge 阻断** | 枚举参数化用例（TC-ENUM-02 的 12 字段非法值矩阵）全绿——防 DTO 校验被误删 | 每次 PR |
| **merge 阻断** | 前端 build + Vitest 关键组件全绿 | 每次 PR |
| **merge 阻断** | Flyway 迁移测试（干净库 + 存量数据集）通过 | 涉及 DDL 变更的 PR |
| 夜间 | E2E 全量（三浏览器矩阵） | 每日 |
| 周任务 | 性能、安全扫描 | 每周 |

> 不进 merge 门禁的（E2E 全量、性能、安全）失败时发告警并列入晨会，不阻断合并。

## 6. 上线割接操作检查单（人工执行类用例载体）

人工执行类用例（TC-SMOKE-01、TC-MIG-02/08/12、TC-SCH-07、TC-MIG-06/07）不进 CI，改由本检查单承载：**操作员按步骤执行 → 按判定行得出结论 → 测试工程师见证签字 → 签字件归档**。

```bash
# ① 持久性第一关（TC-SMOKE-01）
#    建 1 员工 + 1 通行记录 → 重启应用 → 复查仍在

# ② 导入管道（TC-MIG-02 步骤① + TC-MIG-08）
docker exec -i smart-park-mysql sh -c \
  'exec mysql --defaults-extra-file=/run/secrets/bak.cnf --default-character-set=utf8mb4 smart_park' \
  < /import/xxx_inserts.sql 2> /import/import_err.log
[ -s /import/import_err.log ] && echo "导入有错 → FAIL" && exit 1   # 日志必须为空

# ③ 零值日期与 sql_mode（TC-MIG-02 步骤②③）
#    SELECT COUNT(*) FROM access_record WHERE pass_time='0000-00-00 00:00:00';  → 0
#    SELECT @@sql_mode;  → 含 STRICT_TRANS_TABLES

# ④ 原子性 + 列序保护（TC-MIG-08）
#    4a 含脏日期行的测试 CSV 导入后：SELECT COUNT(*) FROM <目标表>;  → 0（行数>0 即 FAIL）
#    4b 列序打乱的 CSV：转换阶段必须报「列名不匹配」并整体中止；若生成了 .sql → FAIL

# ④' 编码与业务键预校验（TC-MIG-12）
#    GBK 文件：转换必须中止并提示「请用 Excel 另存为 CSV UTF-8」；若自动转码继续 → FAIL
#    含小写工号 e1001 / 非法 status「再職」的 CSV：转换阶段报错并给出行号

# ⑤ 时区（TC-MIG-06）
#    另：确认 02:30 备份任务已产出当日备份文件
#    SELECT NOW(), UTC_TIMESTAMP(), @@global.time_zone, @@session.time_zone;  → 一致且为北京时间
```
